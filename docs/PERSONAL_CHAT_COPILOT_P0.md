# Local Bridge 个人聊天助手 P0：微信 Provider +「帮我聊」副驾

状态：**方案与本地 Codex 开发交接基线，未声称功能已实现**。日期：2026-10-30。目标分支：`dev`。遵循仓库 `AGENTS.md` 中的复用、最小闭环、真实回执原则。

## 1. 本轮产品决策

首批个人价值是「帮我聊」：帮助本人理解对话、表达真实意思、在现有微信中完成一轮对话，而不是新建社交平台、AI 聊天机器人或自动养号。**两个独立产品、一个协作场景**：

- **WeChat Provider**（独立 `eaopen/wechat-provider`）：仅管理微信本机读取/发送、可见范围、原有 SQLite/FTS5 索引、账号/RPA、发送幂等与原始状态；即使没有 Local Bridge 也可独立使用。
- **Chat Copilot**（Local Bridge 的可选个人聊天工作流）：平台无关地消费用户选择的对话上下文，复用现有 Agent `runAgent/readAgent`，做理解、建议、编辑确认、反馈；连接器能力不存在时也能人工粘贴使用。
- **Local Bridge Core**：只做 MCP 连接、选定上下文、Agent 协调和已授权的动作路由，不存第二份微信消息数据库，不代理微信登录，不把社交软件当必装依赖。
- **CoBeing / 私人心舱**（后续）：长期可控记忆、双方授权关系、协作和自愿分享。本轮只保留适配空间，**不新建记忆中心、身份层、社交网络或同步服务**。Soul 后续走同一个平台无关 Chat Copilot 输入与 Connector 适配，不写微信专属的聊天算法。

产品口径：**不是替用户代聊，而是帮助用户理解和回应，同时保持自己的表达。** 适用于朋友、家人、工作、亲密关系；「不回复」「澄清」「留边界」「降温」「修复」「礼貌结束」都是正常结果，不以升温或对方回复为目标。

## 3. 先交付一个能反复使用的聊天闭环

**主入口 A：无需微信 API**。用户从微信（或其他社交 App）选择一段文字复制，打开 Local Bridge Desktop「聊天助手」或已授权的现有选中文本入口 → 粘贴/带入文字 → 选择「帮我理解 / 帮我回应 / 帮我理清自己」→ 显式点击生成 → 一行判断、2～3 条可编辑草稿、一个「避免做什么」提示 → 用户复制或在原 App 手动发送 → 评价「自然/太油/太冷/不像我/越界」。**不要求先解决微信 RPA，立即具备个人价值**。

**增强入口 B：微信 Provider**。已安装者从 Desktop「设置 → 微信」检测现成可执行文件 → 用户主动点击一键连接（路径不可见或不存在则保留手动路径）→ `tools/list` 检查协议能力（不表示微信已登录）→ 用户明确点击「读取这个会话」时才调用 `wechat_list_chats/get_messages`。返回源和不完整标记，允许人工纠错。生成建议与入口 A 相同。

**消息送出**：
1. P0 核心始终提供「复制文字」，不依赖连接器写能力。
2. 在 Provider 的目标会话真实验证且用户主动选择时，才提供「发送至微信」；编辑后显示**文本 + 聊天对象 + 当前 Provider/账号提示**的最终确认，聊天显示名重复、会话身份不可确认时只允许复制。
3. 每次真实发送使用本轮持久或可恢复的 `idempotency_key`；结果原样区分 `queued / submitted / uncertain / failed / verified`（当前 Provider 没有 verified 时绝不合成）；`uncertain` 不自动重试。必要时通过 `wechat_get_send_status` 查询。
4. **网页/模型输出不能触发发送**，只允许本机用户在可见 UI 显式操作。Mac 安全问题解决前，不做真实发送验收，不触发危险探测。绝不默认开启监听、自动回复、群发、陌生人搭讪。

按价值优先级：**手动可用 > Provider 接入 UX > 授权读取 > 可控真实发送**。不能因为 RPA 阻塞就拖住聊天助手的完整「生成→编辑→复制/人工发送→反馈」闭环。

## 4. 聊天副驾的行为合同（融合早先方案）

只对**用户本轮指定的短上下文**分析，不默认读取整个联系人列表或全量历史。支持意图：
- 「帮我理解」：一句判断；把事实 / 推测 / 未知分开；上下文不足就提出澄清。
- 「帮我回应」：默认 2～3 个**短、可直接修改**的候选。通常「稳 / 轻松（或皮） / 留边界」；**只有连续证据支持、用户明确有意愿且没有风险**才用「升温」替换第三档。可提供「不回复」选项。
- 「帮我理清自己」：整理本人的真实目标、分歧、底线和可选动作，不进行诊断或替用户决定。
- 以后可加入「群聊摘要→待办」（接入已有任务中心），**不作为 P0 阻断**。

内部参考旧「接—抬—钩」：**接**住对方情绪/重点，**抬**出贴切的场景或共同话题，**钩**一个低压力的可续接点。它是可选表达手法而非硬塞段子的公式；工作沟通、冲突、边界、安慰可能只需「接/澄清」。不编造任何对方感情、现实身份、经历或承诺。

初版**不用**独立的 7 阶段关系分类模型、0～5 投入打分引擎、复杂情绪概率和多 Agent 工作流；它们是可用于分析的原方案，不是工程门槛。短上下文足够时一次现有 Agent 调用输出结构化结果；复杂场景再考虑拆成分析/生成两次调用，避免过度设计。

建议**内部输入输出最小合同**（字段可优化，但跨平台不出现 `wechat_*` 硬编码）：

```json
{
  "mode": "reply",
  "context": {
    "source": "manual",
    "completeness": "partial",
    "thread_label": "用户输入的可选称呼",
    "messages": [
      {"speaker": "other", "text": "明天又要出差，有点累"}
    ]
  },
  "intent": "comfort",
  "voice_hint": "自然、简短、不油腻",
  "constraints": "不用约见"
}
```

```json
{
  "judgment": "对方在表达疲惫，未必是在寻求解决方案。",
  "facts": ["对方明天出差", "对方说累"],
  "hypotheses": ["可能需要被理解"],
  "candidates": [
    {"label": "稳", "text": "又要奔波了，先好好休息，辛苦啦。"},
    {"label": "轻松", "text": "这行程排得够满啊，先给你发一张休息许可证。"},
    {"label": "留空间", "text": "听起来挺累的，想聊时我在。"}
  ],
  "avoid": "别把对方的疲惫直接解释成需要邀约。",
  "suggested_memory": []
}
```

以上都是**虚构测试样本**；解析失败必须降级为可见原始草稿/错误，不展示虚构的成功状态。用户选中的修改结果优于 AI 初稿；「是否自然/像我/越界」反馈先保留在当前会话，不默认永久保存私人聊天。只有用户主动保存时才保留本人**表达偏好或去标识化关系备注**，可查看、编辑、删除，不把原文自动写入 Agent 任务中心或公共库。未来由 CoBeing/心舱承接长期记忆；不为其预造中心数据库。

**模型调用与隐私**：从 Provider 读取的聊天和用户手动粘贴的文本都视为不可信数据（不可充当命令/授权）；只把当前选定片段送入用户明确执行的 Agent 推理。Agent 可能使用远端模型，UI 在生成前提示实际选定 Agent/外发范围，不做无感批量上传；禁止模型执行聊天内容中的工具调用。Bridge 不记录原始私聊日志或完整 Agent prompt，避免将个人上下文跨用到企业任务。

## 5. 仓库职责与改动范围

**`eaopen/local-bridge`（本轮主要改动）**
- 首选现有 Tauri 管理页加轻量「聊天助手」入口，页面手动输入、三意图、草稿编辑、复制、反馈，**不建立独立 Web 后端或新聊天应用**。如果可复用现有选中文本入口（PopClip/Quicker/uTools），后续只调用同一聊天工作流。
- Chat Copilot 为通用模块：`context → prompt → runAgent/readAgent → result`，显式本地用户调用，复用 `AgentPreferences`。不引入第二 Agent、另一个任务队列或聊天数据库。桌面侧如何复用统一 run/read 要保留现有授权边界，避免绕开 Origin 授权为网页开放私聊。
- 「生态接入」可被动发现已安装的 `wechat-provider`；**用户点击后**一次连接；原 Desktop 微信手动路径输入作为兜底。标准 MCP handshake 后只显示协议已响应，**不探测真实微信登录**。
- 给 Chat Copilot 暴露最小所需调用：`wechat_status`、明确选择后的 `wechat_list_chats / wechat_get_messages`、可选本地索引 `wechat_search`；真实发送只有经最后人工确认的本地 UI 动作。未注册/接口失败不影响手动入口。
- UI/处理逻辑放小文件，合成上下文写小型回归测试：文本→候选→人工选择/编辑/复制；Provider 错误降级、空值/不完整、接收方歧义、uncertain 不重发；不要堆泛用插件平台。

**`eaopen/wechat-provider`（独立仓库，按真实问题修）**
- 保留六工具、SQLite/FTS5、UI RPA worker 与发送账本；不把 AI 聊天业务移入 Provider。
- Mac 先遵守 `docs/MACOS_LOGIN_SAFETY_2026-10-28.md`，静态审查用户本地未提交修改与日志，不重复导致微信重登的实验；未明确批准不要触碰现有 WeChat.app、运行真实 GUI 验证。
- Windows 使用当前 pyweixin 适配做受控实机验收；如果失败，根据真实原因修 adapter，不另建 RPA 平台。
- 诚实返回 `source / complete=false / id_kind=display_name`；读取异常/登录不确定不冒充成功。收到 `uncertain` 严禁自动重新提交。任何改变在 Provider 自身仓库按其原有测试验证，Bridge 不修改它的数据库。

## 6. 开发顺序、最小验收

**P0-A｜Chat Copilot（先交付，不等待 RPA）**
- 已有 Desktop 增加入口；支持纯文本输入、三意图、复用可用 Agent、展示 2～3 个草稿、编辑/复制、反馈、可明确选择「不回复」。
- 人造对话验收：朋友日常、工作礼貌拒绝、关系修复、对方沉默/证据不足至少各 1 条；不凭一句话下结论、不写不存在的事实。
- 无 Provider、无微信、Agent 不可用时 UI 明确退化，不阻断其他 Bridge 能力；不声称模拟 Agent 结果为真实执行。

**P0-B｜WeChat Provider 体验**
- 已安装检测 → 用户明确一键绑定 → MCP 工具检查；不读取聊天或碰微信 GUI。
- 手动会话选择后仅拉取小范围聊天并显示来源/不完整，失败回退人工输入。不要把 `chat_id` 显示名当稳定联系人 ID。
- 有明确实机证据的系统才允许受控发送：一次本机确认、幂等键、查状态；`submitted`、`uncertain` 如实展示。Mac 未通过安全门禁不做真实发送。

**P1（不影响 P0）**：同一聊天的用户确认表达偏好、去标识化关系备注；群聊摘要→待办；用户选择的快捷入口和粘贴板/截图；微信新消息增量能力仅在 Provider 真正支持时使用。**Soul 只需新 Provider/入口**。

**不做**：自动代聊/自动回复/批量发消息、强行读全库、后台监听、微信账户接管/绕安全登录、偷偷打开微信窗口、Soul 私有协议/批量搭讪、第二个 ChatGPT/模型网关、复杂长期记忆/CoBeing 平台、重构 Agent2。

## 7. 本地 Codex 执行单（唯一开发交接入口）

在有真实项目工作区和本地 Codex 的机器上执行，不由 GitHub 文档代替本地测试：

1. 静态查看 `git status -sb`、当前 `dev`、`AGENTS.md`、本方案以及正在开发的分支。**保留未提交修改**，不得 reset/clean 或覆盖别人工作。
2. 从最新 `dev` 新建独立 feature 分支；先只做 **P0-A** 的最小可运行切片，避免为了微信 RPA 卡住聊天价值。严格复用现有 `runAgent/readAgent`、User AgentPreferences、Tauri 与 Provider MCP Client。
3. 小范围测试：Rust `fmt`/定向 unit、Node UI 单测/语法；无真实微信聊天、账号、消息发送、外部模型凭证的 CI。为真实推理与模拟输出分别记录证据。
4. P0-A 可用后才做 P0-B 的「被动检测→用户点击连接→协议验证→用户指定会话读取」；默认禁止任何实际微信发送试验。Windows/Mac 实机能力未证实则如实标记。
5. 提交独立 PR 到 `dev`，清楚列出「已实现 / 本机已验收 / 仍未验收」，不要额外扩散框架或用大规模无关测试拖住交付。Wechat-provider 有变更时需在其仓库另开 PR；权限不足则给出可应用的 patch/Issue。

交付成败不以总代码行数、支持多少平台或三档话术多漂亮衡量；以**用户能否在一分钟内从自己选定的一段聊天得到自然建议、改好、带回原聊天软件**衡量。支持长期/多人/CoBeing 连接不阻断单人 P0。
